## git 如何查找被删除的历史文件


Git 的设计机制是不会真正“删除”数据的，它只是记录了文件在某个时间点的状态。因此，无论是被删除的还是修改的历史文件，只要尚未经过垃圾回收（Garbage Collection），理论上都是可以找回来的。

查找方法取决于您想知道的是 **1. 它是否存在** 还是 **2. 恢复其内容**。

---

### 🔍 方法一：查询文件的历史记录（它何时存在/被删除）

如果您只是想查看某个文件在提交历史中的变动，可以使用 `git log`：

```bash
# 查看特定路径文件的所有提交历史
git log -- follow <file_path>
```

如果该文件在某次提交后才消失，但其记录仍然存在于父节点（Parents）中。

### 🖼️ 方法二：恢复被删除的文件内容（推荐方法）

如果您知道文件曾经存在于哪个提交点（Commit Hash），您可以使用 `git show` 命令来“查看”该时间点的文件内容，并将其导出或临时检出到工作区。

**语法：**

```bash
# 格式：git show [目标提交ID]:[文件路径]
git show <commit_hash>:<file_path> > recovered_file.txt
```

*   `commithash`：您怀疑该文件存在的时间点。
*   `file_path`：文件的相对路径。
*   这个命令会从历史记录中提取出该提交时该文件对应的**内容快照 (Blob)**，并将其保存到当前目录。

### 🗑️ 方法三：查找某个范围内的变动（Diff）

如果您不记得文件具体的名字或提交ID，但知道它在 **A 版本** 和 **B 版本** 之间被删除/修改了，您可以使用 `git diff` 查看差异列表。

```bash
# 查看从 A 提交到 B 提交之间的所有文件变动（包括新增和删除）
git diff --name-only <commit_A>..<commit_B>
```

---

### ✨ 总结要点 (Cheat Sheet)

| 目的           | 命令示例                              | 说明                                   |
|:---------------|:--------------------------------------|:---------------------------------------|
| **查看内容**   | `git show abcdef:path/file.txt`       | 从特定历史提交中提取文件的内容。       |
| **查文件路径** | `git log -- name-only ...`            | 查看指定时间范围内变动的完整文件列表。 |
| **恢复文件**   | `git show <commit>:<path>` > file.txt | 将目标版本的内容导出为实际文件。       |


## You have divergent branches and need to specify how to reconcile them.

想象你和朋友 小明 各自复制了一份同一篇文章（同一个 Git 仓库），你们分别在同一份稿件的不同地方修改：
- 你加了开头段落后 git commit（本地提交）
- 小明改了结尾标点后 git push（远程推送）
这时你们的修改路线就像两条岔路——它们 diverge（分道扬镳）了。当你执行 git pull 时，Git 发现：
你手里有本地没有的远程提交（小明的）；远程也有远程没有的本地的提交（你的）。
两条路都要合并进来，但 Git 需要你告诉它怎么合并：

| 策略          | 比喻                                                                                           |
|:--------------|:-----------------------------------------------------------------------------------------------|
| merge（默认） | 你的路线和小明的路线各走各的，最后汇合时产生一个合并路口（merge commit）                       |
| rebase        | 把你的改动先放一边，等小明的路线铺好，再把你的改动铺到小明路线的最顶上，就像你从来没分过叉一样 |
| ff-only       | 只有你的路线完全在远程后面（没有分叉），才允许合并；有分叉就拒绝，让你先手动处理               |

解决方案（选一种跑一次）：
git config pull.rebase false   # 以后默认 merge（安全，保留历史）
git config pull.rebase true    # 以后默认 rebase（历史更线性，但要小心公共分支）
git config pull.ff only        # 以后只接受快进（保守，逼你手动处理分叉）
如果你想这次解决，可以直接：
git pull --rebase   # 或者 git pull --no-rebase

## .gitignore 忽略某个文件夹，然后排除忽略那个文件夹里某些文件

标准写法：

```
# 忽略 mydir/ 下所有内容
mydir/*

# 但保留某些文件
!mydir/keep-me.txt
!mydir/.gitkeep
```

关键规则：

| 规则 | 说明 |
|------|------|
| 用 `mydir/*` 而非 `mydir/` | `mydir/` 会忽略整个目录，Git 不进入该目录，导致 `!` 排除失效 |
| `!` 排除只对已追踪的文件生效 | 先恢复目录，再恢复文件 |
| 排除不递归 | `mydir/*` 只匹配直接子级，更深层用 `mydir/**/*` |

如需恢复深层文件：

```
mydir/*
!mydir/.gitkeep
!mydir/subdir/
!mydir/subdir/important.txt
```
