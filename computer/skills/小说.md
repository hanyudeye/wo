### ⚙️ Project Name: Chronos Engine (时间循环引擎)
### Goal: Sustained Narrative Tension via Logical Constraint

#### 🧱 Phase I: 初始化与约束设定 (The World Rules / State Definition)

这是所有叙事的基础，必须**强制写入系统内存**，并在后续生成中作为硬性约束执行。

1.  **`DEFINE_SETTING(World)`:**
    *   **输入 (Input):** 硬科幻/赛博朋克的核心概念（例如：神经连接、能耗循环、数据壁垒）。
    *   **输出 (Output):** 一份不可更改的“宇宙物理法则清单”（Rulebook）。
        *   *示例格式:* `RULE_ID-001: 所有信息传输必须通过量子加密网，能量消耗与其熵增比值成正比。`
        *   *约束检查点:* 任何提出的主角行为或设备功能，如果违反了此清单中的任一规则，则判定为**矛盾（Contradiction）**并被自动修正/解释失效。

2.  **`DEFINE_ENTITY(Characters)`:**
    *   设定核心角色、他们的技能集和他们在世界观下的“物理定位”（即：资源获取能力、社会权限）。
    *   重点定义主角的**认知盲点（Blind Spot）**，这是矛盾引出的角度。

---

#### 🎯 Phase II: 启动冲突锚定 (The Anomaly / Mystery Seed)

这是整个小说的初始催化剂。它必须是一个系统性的、无法被当前规则体系解释的“缺陷”。

1.  **`INCITE_DEFECT(Anomaly)`:**
    *   **目标：** 不应是人物间的冲突，而必须是**环境或系统本身**的矛盾点。
    *   **生成机制：** 选取 `Rulebook` 中两条看似无关但逻辑上可能互相排斥的规则（例如：A规则设定了信息绝对不可逆；B规则的观测设备却展示了回溯信号）。
    *   **输出 (Output):** 一个具体的、无法被主角现有知识体系解释的现象。这是整个故事必须围绕解决的“悖论核心”。

---

#### 🔄 Phase III: 核心生成循环 (The Information Feedback Loop)

这是小说的执行引擎，它是一个强制性的迭代流程，每完成一次场景（Scene），就必须走完以下三个子步骤。**这是保证持续吸引力的关键。**

**(Core Generation Loop: Run Until Conflict Resolution or Defined End Point)**

| Step | 目标功能 | 执行逻辑 (Function) | 产出要求 (Mandatory Output) |
| :--- | :--- | :--- | :--- |
| **3.1 Setup** | **动机/尝试 (The Action)** | 主角根据现有资源和知识，试图解决 `Anomaly` 的一个小切面。动作必须在 `Rulebook` 内合理化。 | 明确的行动链（Action Chain）与一次重大的系统消耗或风险暴露。 |
| **3.2 Conflict** | **反制/升级 (The Escalation)** | 系统必须阻止主角。障碍不能是纯粹的情节冲突，而必须是**规则层面的物理/逻辑反制**。每一次尝试失败，都要导致角色认知和环境理解的“升级”。 | 引入新的、更高阶的系统限制（例如：原来以为的缺陷只是一个烟雾弹；真正的缺陷在A规则的边缘）。 **核心原则：Fail Hard, Learn Harder.** |
| **3.3 Feedback** | **悬念反馈 (The Loop Close)** | 这是最关键的一步。不能给答案，只能给出碎片和新的约束。 | 必须包含以下两个强制元素：<br> ① **[NEW_INFO]:** 一个无法被主角（读者）忽略的新信息/线索。<br> ② **[SYSTEM_DEMAND]:** 一个不可避免的、来自世界设定的新要求或压力点，迫使主角进入下一回合。 |
